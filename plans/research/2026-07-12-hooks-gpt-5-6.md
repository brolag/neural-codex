# Research: neural-codex hooks and GPT-5.6 refresh

Date: 2026-07-12

## Summary

`neural-claude-code` ships five hook behaviors worth preserving, but its scripts
use Claude-specific environment variables, input fields, tool names, and timeout
units. Codex now has native lifecycle hooks, so the safe route is a semantic port
to `.codex/hooks.json`, not a direct copy.

GPT-5.6 is the current OpenAI frontier family. The `gpt-5.6` alias routes to
`gpt-5.6-sol`; current prompting guidance favors lean prompts, explicit autonomy
and approval boundaries, measurable success criteria, and representative evals
instead of automatically maximizing reasoning effort.

## Key findings

- Codex discovers project hooks in `.codex/hooks.json` and requires users to review changed hook hashes with `/hooks`.
- Codex hook timeouts are seconds. `PreToolUse` sees simple `Bash`, `apply_patch`, and MCP calls; it is not a complete enforcement boundary.
- Post-tool output is supplied as `tool_response`, not Claude's `tool_output`.
- Codex 0.134+ replaced inline `[profiles.*]` tables with `$CODEX_HOME/<name>.config.toml` overlays.
- Current Codex exposes native web search through `codex --search`; the old default Exa SSE stub returned HTTP 404 and should not load on every startup.
- GPT-5.6 supports a wider reasoning range, but migrations should preserve the current effort as a baseline and compare one level lower on representative tasks.
- GPT-5.6 prompting should state goals, context, hard constraints, approval boundaries, success criteria, and required output while removing repeated instructions.

## Implementation decision

Port the five behaviors as Python standard-library hooks, install them at project
scope, and document known interception gaps. Refresh the bundled config to current
Codex keys and provide global profile overlays using GPT-5.6 with different
reasoning/approval trade-offs. Validate hook behavior with event fixtures and
validate TOML using the installed Codex CLI's strict-config mode.
